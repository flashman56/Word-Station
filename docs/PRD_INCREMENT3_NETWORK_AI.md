# 词根词缀单词云：增量3（网络掌握全景 + AI 扩词 + 交互精简）PRD

> 文档状态：可进入设计拆解（分阶段确认）  
> 适用范围：在增量2（学习闭环，310 词，v2 学习记录）之上，**仅描述相对已有产品的变更**。  
> 上游依据：`docs/PRD_LEARNING.md`、`docs/DESIGN_LEARNING.md`（口径、三态配色、morphs 词素库存、v2 学习记录模型均沿用，不回退）。  
> 字段口径对齐：背景所述「type / meaning」分别对应实际数据字段 **`pos` / `gloss`**；本 PRD 一律使用真实字段名，避免与现有数据文件冲突。  
> 三态配色沿用既有 `STATUS`（`未知 #c9484b` / `待复习 #c98a17` / `已掌握 #9aa1ac`），组件不得硬编码颜色。  
> 执行顺序（用户拍板）：**3-A AI 扩词 → 3-B 网络图 → 3-C 总览查找 → 3-D 按钮改名**；每阶段完成并确认后再进入下一阶段。

## 1. 产品目标

把「310 词的词根词缀学习闭环」升级为「约 2000 词、以共享词根/词缀为主连线的单词关系网络全景」：用户能在总览里**直观看懂词与词之间靠哪些词根相连、自己到底掌握了哪一片**，同时通过一次性离线 AI 扩词（零运行时成本）解决「词太少一下背完」的痛点，并把学习卡片简化为「记得 / 不记得」一步确认。

---

## 2. 用户故事

1. **作为背词用户**，我想在总览里看到一张单词关系网：点一个词，它和“共享同一词根”的词被线连起来、其余变暗，我立刻知道「spect 这一族我掌握得好不好」，而不是在一堆气泡里自己拼。
2. **作为中高阶学习者**，我想在不调用 AI、不上传数据的前提下，把词库从 310 扩到约 2000（雅思~GRE 难度），这样每天都有新词可背，且每个新词都带词根拆解、音标、例句与语义关系。
3. **作为想看清进度的用户**，我希望网络图里的节点按「未知 / 待复习 / 已掌握」三色着色，顶部一行告诉我「我会了多少」，背词成果一眼可见。
4. **作为检索型用户**，我想在网络视图上方输入单词 / 词根 / 释义关键词，实时过滤并自动聚焦命中节点，不用在 2000 个点里肉眼找。
5. **作为怕误触的用户**，我希望学习卡片只问「记得 / 不记得」两个选项——点「记得」一次就标记为已掌握，点「不记得」就进待复习，不再有「连续答对 2 次」的门槛和中间态迷惑。

## 3. 数据与模型变更（增量基础，3-A 前置）

> 仅描述新增 / 变化部分；`id / form / pos / gloss / morphs / chain / phoneticBr / example / freqRank / cefr` 沿用既有定义。

### 3.1 新词（AI 批量产出）字段要求

| 字段 | 类型 | 必填 | 说明 | 来源 |
|---|---|---:|---|---|
| `id` | string | 是 | `'w.' + 单词`，**全库唯一**（含现有 310 词） | AI 生成+脚本去重校验 |
| `form` | string | 是 | 词形 | AI |
| `pos` | string | 是 | 词性，沿用 DJ 之外现有写法（如 `v.`/`n.`） | AI |
| `gloss` | string | 是 | 中文释义 | AI |
| `morphs` | string[] | 是 | 词素 id 数组，**只能引用既有 `morphemes.js` 中的 id** | AI（须给词素库存） |
| `chain` | object[] | 建议 | 有序构词拆解（可含 `morph: null`） | AI |
| `phoneticBr` | string | 是 | DJ 英式音标，含首尾斜杠 | AI |
| `example` | `{en, zh}` | 是 | 双语例句，须与 `gloss` 义项一致 | AI |
| `freqRank` | number | 是 | 频率排名（越小越常见）；新词集中在高频 310 之后区间（建议从 ~18000 顺延，量级贴合 IELTS~GRE） | AI 估计 |
| `cefr` | `'C1'\|'C2'` | 是 | 新词难度区间（雅思~GRE） | AI |
| `synonyms` | string[] | 否（语义图层用） | 同义词 `form` 列表 | AI |
| `antonyms` | string[] | 否（语义图层用） | 反义词 `form` 列表 | AI |
| `themes` | string[] | 否（语义图层用） | 主题标签，如 `['science','emotion']` | AI |

**关键约束**：`morphs` 必须命中既有词素库存，否则网络主连线无法生成。开发脚本须（a）在 prompt 中附完整词素清单，（b）生成后用 `validate-data.mjs` 复用校验逻辑，凡 `morphs` 含未知 id 一律报错拦截，不得入库。

### 3.2 语义关系字段的解析与落地

- `synonyms` / `antonyms` 以 **`form` 字符串**存储（不强制要求引用库内 `id`，避免 AI 编造不存在的 id）。运行时构建 `form → id` 映射，仅当两端都在库内时才绘制语义边。
- `themes` 为自由标签，用于语义图层按主题着色 / 聚合，不要求与词素体系一致。
- 现有 310 词**可不补**语义字段（默认空数组）；语义图层开启时，它们只参与 morph 主连线，不参与语义边（除非后续补充）。

### 3.3 词库规模与统计口径变更

- `derive.js` 中 `STATS_SCOPE = 310` 必须改为**动态值**（= 全库去重词数，扩词后约 2000）。进度条、三态统计、学习/复习队列分母全部跟随动态总数。
- 学习池 / 高频继承等增量2 口径（§0 口径修正）在 310 部分继续有效；新增约 1690 词默认 `unknown`，进入学习队列。

### 3.4 持久化

- v2 学习记录结构（`wrc.learn.v2`）**不变**；新增词无记录时按 `emptyRecord()` 计算，不为新词预写空记录（沿用既有不变量）。
- 扩词为纯数据增量，不触发迁移脚本重跑；旧 `wrc.learn.v2` 中的 `records` 按 `wordId` 自然兼容（未出现的新词 id 视为 `unknown`）。

## 5. UI 设计稿

### 5.1 总览 = 网络关系图（核心）

```
┌──────────────────────────────────────────────────────────────────────┐
│ 总览 · 单词关系网                                          [网络▼|气泡] │
├──────────────────────────────────────────────────────────────────────┤
│ [🔍 搜单词/词根/释义___________]   图层: ☑ 词根连线  ☐ 语义连线       │
│ 我会了：已知 320 · 待复习 45 · 未知 1635  (共 2000 · 掌握 16%)         │
│                                                                        │
│        ┌─────────── 画布区（力导向） ───────────┐                      │
│        │    (spect)●inspect ────●respect         │                     │
│        │         │  (共享 r.spect:看)            │                     │
│        │         ├──●perspective  ──●spectator   │                     │
│        │         └──●conspicuous                 │                     │
│        │    ●portable ──(r.port:运)──●transport  │                     │
│        │    ●abolish  ──(themes:law)──●pardon   │  ← 语义图层开时显示 │
│        │                                        │                     │
│        │  节点颜色：●未知 #c9484b ●待复习 #c98a17 │                     │
│        │            ●已掌握 #9aa1ac              │                     │
│        └────────────────────────────────────────┘                     │
│   点击节点 → 高亮邻居+边，其余变暗；右侧/底部弹出该词详情              │
└──────────────────────────────────────────────────────────────────────┘
```

**交互细则**
- **连线规则（主）**：两词 `morphs` 有交集即连；边上标注共享词素的 `gloss`（如 `r.spect: 看`）。同一词素下的多个词构成局部簇。
- **高亮/淡化**：默认全图可见；点（或悬停）某节点 → 该节点及其邻居+边高亮，其余节点与边降透明度（不移除），便于「看我到底会了这一族多少」。
- **性能策略**：2000 节点下，全量边（每词素一个 clique）规模极大，**默认只绘制选中/悬停节点的邻边**，其余边在缩放或明确请求时再绘制（见 R-15）。
- **节点详情**：复用在 `App.jsx` 的 `WordDetail` 结构（gloss、chain 拆解、双语例句、状态徽标、`x/2`、累计答对/答错、最近学习、操作按钮），不另造一套。
- **语义图层（R-11/R-12）**：默认关。开启后叠加 synonyms（建议绿色实线）/ antonyms（建议红色虚线）/ themes（按主题着色或画主题圈）；与 morph 主连线可同屏叠加，颜色明显区分。

### 5.2 StudyCard 改为两按钮（3-D）

```
┌─────────────────────────────┐
│ 3 / 10                      │  ← 轮次进度不变
│                             │
│       inspect               │  ← 单词主视觉
│     /ɪnˈspekt/    v.        │  ← 音标 + 词性
│   你记得这个词吗？           │
│                             │
│  [   不记得   ] [   记得   ] │  ← 两等宽按钮
│                             │
│  —— 作答后展开同既有答案区 —— │
│  检查；视察                  │
│  The committee will ...     │
│  委员会将检查……              │
│  [ 构词拆解: in- + spect ]   │
│  已掌握 2/2  / 已加入待复习   │
│        [ 下一个 ]            │
└─────────────────────────────┘
```

- 「不记得」= 原「不认识/答错」→ `review`，连续答对归零。
- 「记得」= 原「我会了」→ 一次直达 `known`，`consecutiveCorrect=2`、`statusSource='manual-known'`、累计次数不变。
- 复习卡片（R-14）同步为同款两按钮；详情/列表/批量三处「我会了」行为保持与 `markKnown()` 一致（既有不变量不变）。

### 5.3 总览查找（3-C）

- 搜索框置于总览顶部（5.1 示意）。
- 匹配维度：`form` 包含、`morphs` 命中（含词素 `display`/`variants`/`gloss`）、`gloss` 包含。
- 行为：输入即时过滤；命中节点高亮并自动 `fit` 到视野中心；无命中显示「无匹配」；清空恢复全图。
- 与图层开关、节点三态配色正交，互不覆盖。
